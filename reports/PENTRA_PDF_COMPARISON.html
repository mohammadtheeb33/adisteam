6. الفجوات (مع الأدلة)

6.1 فجوات مشتركة لا تحققها أي نسخة

G-01عالٍالثلاثةاستدعاءات النظام (Auditd / eBPF) غير موجودة
المطلوب
نوع بيانات كامل في جدول §2.3: «استدعاءات النظام ← Auditd، eBPF ← تسلسلات استدعاء». و adis.pdf يضع eBPF ضمن تقنيات الطبقة 1.
الواقع
لا مجمّع في أي نسخة. الأساسي لديه مخطط ProcessEvent بلا مصدر (ميزات العمليات في Phase 2 دائمًا صفر، OD-25). muna Windows فقط. omran شبكة فقط.
الأثر
لا رؤية لسلوك العمليات على مستوى النواة؛ هجمات رفع الصلاحيات (LinPEAS في سيناريوهات §8) لا تترك أثرًا مجمّعًا.
الحل
مجمّع auditd على Linux كبداية (قراءة فقط، بلا تغيير سياسات التدقيق تلقائيًا)، ثم eBPF في مختبر؛ وعلى Windows حدث 4688 أو Sysmon كمكافئ.
G-02متوسطالثلاثةلا استقبال لـ Syslog
المطلوب
§2.3: سجلات النظام من Syslog و Windows Event Log.
الواقع
الأساسي يقرأ ملفات log المحلية فقط (ومنها ملفات syslog كأسطر خام)، بلا استقبال Syslog من أجهزة أخرى (UDP/TCP 514 أو RFC 5424). muna تذكر أن مجمّعات Linux «اختيارية وغير منفذة». omran لا شيء.
الأثر
خوادم Linux والجدران النارية وأجهزة الشبكة لا ترسل سجلاتها.
الحل
مُستقبِل Syslog يحلل RFC 3164/5424 إلى SystemEvent، يستمع على عنوان مسموح فقط.
G-03متوسطالثلاثة«ملايين الرسائل في الثانية» غير مُثبت
المطلوب
§2.1: Kafka يتحمل ملايين الرسائل ولا يفوت أي نشاط في أوقات الذروة.
الواقع
الأساسي: أعلى معدل استقبال مُقاس 678 حدثًا/ثانية، وخط الأنابيب الكامل 7–13 حدثًا/ثانية (docs/PHASE_7_RELIABILITY_EVALUATION.md)، وعلى Supabase المستضاف 0.16 حدث/ثانية. muna: لا قياس، طلب HTTP لكل حدث. omran: طلب + flush لكل حزمة. والثلاثة تعمل على broker واحد بلا تكرار.
الأثر
الرقم في pentra.pdf وصف لقدرة Kafka نفسه، وليس لهذا النظام؛ عنق الزجاجة في HTTP والقاعدة والمعالجة، لا في Kafka.
الحل
تحديد هدف واقعي مُقاس لـ Phase 1 (مثلًا أحداث/ثانية لكل Agent ولكل بوابة)، اختبار حمل له، وتوثيق الفرق عن نص pentra.pdf.
G-04متوسطالثلاثةMTTD أقل من 50 ms غير قابل للتحقيق بالمعمارية الحالية
المطلوب
§10: متوسط وقت الكشف < 50 ms (والجدول يقول «النتيجة المحققة 50ms» نقلًا عن أبحاث).
الواقع
في الأساسي، مرحلة الاستقبال وحدها (من الإرسال حتى adis.security.events) p50 = 63 ms للأحداث المفردة و 617 ms للدفعات؛ و MTTD الكامل المقاس 0.64 s بلا حمل، و 46 s أو أكثر تحت حمل. muna و omran لم تقيسا.
الأثر
الهدف مستحيل ما دام المسار HTTP ← Kafka ← Normalizer ← قاعدة ← Kafka ← كشف. المؤشر في pentra.pdf منقول من الدراسات المرجعية («المذكورة في الدراسة الأصلية»)، وليس مقاسًا على النظام.
الحل
